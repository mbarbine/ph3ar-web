## 2026-03-31 - Optimize signup route by checking if user exists before hashing password
**Learning:** Hashing a password with `bcrypt` is expensive. In `routes/userRoutes.js`, the `signup` route hashes the password *before* attempting to create the user in the database. If the username already exists, the database throws a unique constraint error, but the expensive `bcrypt.hash` operation has already been performed unnecessarily. This allows an attacker to easily perform a Denial of Service (DoS) attack by repeatedly sending signup requests with an existing username, forcing the server to do expensive computations.
**Action:** When creating a user, first check if the username already exists. If it does, return an error early before performing any expensive operations like password hashing.
